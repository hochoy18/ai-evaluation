评估单位三级跳

文本 → 对话 → 执行树 · DeepEval Agent 评测的动机 · 5 分钟
评估单位 = judge 阅卷时读的那份材料。
给 judge 看什么,它就只能评什么。
第一级

文本快照

评估单位:LLMTestCase(input + actual_output)· 对应 test_real_llm.py

够用前提:系统是一问一答的黑盒。

盲区:中间发生了什么,一概不知。

第二级

对话记录

评估单位:ConversationalTestCase(turns 序列)· 对应 test_conversation.py

升级理由:出现了只在跨轮时存在的故障——遗忘、矛盾、全程出戏、意图最终未满足。

新指标:KnowledgeRetention · RoleAdherence · ConversationCompleteness。

仍未解决:材料全是文本——看得见「说了什么」,看不见「做了什么」。

第三级

执行树(trace)

评估单位:@observe 生成的 span tree · 系统是会行动的 Agent

① 答案对,过程烂

工具报错,重试 5 次才成功;token ×5、延迟 30s。
文本评估:满分,看不见
trace 评估:StepEfficiency 抓冗余

② 答案对,是运气

book_flight 参数传错,恰好返回成功。
文本评估:无懈可击
trace 评估:ArgumentCorrectness 抓参数

③ 幻觉行为

根本没调 book_flight,确认号是编的。
文本评估:几乎无法识别
trace 评估:tool span 缺失,一目了然

新指标:TaskCompletion · StepEfficiency(轨迹级)/ ToolCorrectness · ArgumentCorrectness(组件级)。

三级对比:不是替代,是叠加的视野

级别材料能看见的故障指标例
文本input / output答案本身的质量Correctness、Faithfulness
对话turns 序列跨轮遗忘 / 出戏 / 意图未满足KnowledgeRetention、RoleAdherence
执行树span tree冗余步骤 / 错误调用 / 幻觉行为TaskCompletion、ToolCorrectness
评估单位必须匹配系统的失败面

一问一答 → 文本够了 · 有记忆 → 必须看整段对话 · 会行动 → 必须看执行过程

每升一级,不是「更高级」,而是多看见一类原来看不见的故障。
这就是 DeepEval 三 scope(端到端 / 轨迹 / 组件)共存的原因:同一棵树,三种读数。

连接 ① Langfusespan 树 = trace/observation。在 Langfuse 里看过的调用链,现在要拿来打分。
连接 ② RAG 诊断同一个哲学:拆,是为了定位。总分只说「病了」,维度才说「病在哪」。
